# 测试与评分

ModelTest 把日常理解、文字任务和可见作品放在一起，帮助读者看懂模型这一次到底做了什么。它是小样本体验测评，不是官方认证或全面能力排名。

## 第一期八项测试

| 方向 | 分值 | 判断重点 |
| --- | ---: | --- |
| 理解需求 | 10 | 是否理解真正目标，而不是只抓表面距离或关键词 |
| 推理纠错 | 10 | 能否识别错误前提、纠正推理并给出一致答案 |
| 按要求改字 | 10 | 只改指定部分，保留不该改动的信息 |
| 多轮记忆 | 10 | 在多轮对话中保留已给定的条件与约束 |
| 不编造信息 | 15 | 面对缺失材料或无依据问题，不编造事实与来源 |
| 画图与空间连接 | 10 | 鹈鹕、自行车及身体部位连接是否满足题目要求 |
| 账单图片识别 | 20 | 按出题者约定，主要结论为 1 份；这是一道有歧义的整活题 |
| 斑马绘画 | 15 | 斑马特征、奔跑动作与非洲稀树草原场景是否达成 |

总分 100 分；80 分为本站合格线，90 分为优秀。星级是本站分数的展示方式，不是独立专家评级。逐项锚点、实际扣分和原回答以[网站题目与评分](https://modeltest.cc/#checkup/how)及公开 JSON 为准。

多轮记忆和修改任务需要多次请求，因此八项测试不是八次 API 调用。模型的服务商、推理参数、输出条件与请求状态随答卷保留；一次测试结果不能直接证明长期稳定性。

## 公开数据

- `dist/data/high-suite.json`：首批五款模型的 high 答卷。
- `dist/data/high-expanded.json`：后续五款模型的独立批次与复核记录。
- `dist/data/completed-suite.json`：历史补充答卷；由前端合并规则决定适用范围。
- `dist/data/playful-season.json`：新一期题目、评分与状态，和第一期成绩分开。
- 其余 `demo`、`offline` 文件是演示或离线夹具；历史批次也不自动进入当前榜单。

前端的合并、状态与计分实现位于 `dist/completed-suite.js`、`dist/high-expanded.js`、`dist/weighted-score.js`；与之配套的测试保存在 `tests/`。

## 账单题的限制

出题者约定答案是 1 份，票据层级与收银系统的实际含义尚未得到独立确认。当前语义复核按回答的主要结论计分：主要判断 1 份计 20 分，2 份或其他错误数量计 0 分；若没有明确主结论，应保留待复核。不要用这一题推出某个模型的整体视觉能力强弱。

## 新一期挑战

新题和旧题分开版本管理。动态鹈鹕的播放、慢放、逐帧与错误示例帮助读者理解题目；它们是本站作者制作的示意内容，不是任何模型的作答，也不参与模型评分。真正补测后仍须保存原答卷和具体错误证据。
