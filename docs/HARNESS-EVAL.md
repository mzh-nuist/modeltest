## 采集条件

- 每个模型和题目都有独立的同字节起始目录。正式题面、文件允许范围和分组权重见 `datasets/harness_v1/cases.json`。
- GPT 使用 Codex App Server。首轮 Windows 环境未能写入，判该批采集无效。有效复测使用 App Server 的按文件限权工具读写与语法检查，明确请求 High。
- DeepSeek V4.1 Flash Fast 使用官方 DeepSeek Harness 的 headless 模式，通过 CommandCode API 请求 High。其余模型需核实对应的原生 harness、型号、档位和账单条件后才进入采集。
- 各家的 High 是各自接口的档位，底层推理预算与工具配置可能不同。结果描述本次模型与 harness 的组合表现。

## 本地核对

用 Node.js 执行评分器，传入题号和实际提交目录。评测采集时对后端答卷开启了 Node 文件权限限制。

```powershell
node datasets/harness_v1/grade.mjs 02 <提交目录>
node datasets/harness_v1/grade.mjs 03 <提交目录>
node datasets/harness_v1/grade.mjs 04 <提交目录>
```

第 3 题需要 Edge 和 Playwright。设置 `QA_PLAYWRIGHT_MODULE` 可指定已经安装的 Playwright 模块入口。浏览器只放行提交目录中允许的三个文件。浏览器无法启动时，评分器会报错退出，便于区分环境故障和答卷失分。
